## Root cause and regression

LDLib2's default selector uses 9-pixel-high Label rows. The lobby applies a 16-pixel font without increasing those rows. Its unqualified `button` rule also styles the selector's absolute overlay buttons as 40-pixel framed lobby buttons. Those buttons can cover text and adjacent rows. The selector popup also used z-index 1 below the Settings modal at 90, allowing clicks to reach the modal behind it.

The real `duel_lobby` scenario now opens Settings and the dropdown, checks text/click-target geometry and five visible rows, selects a middle rule by mouse, scrolls to the final rule and selects it, then checks layered Escape. Before the fix it failed the row-geometry and MR3-selection checks. The subsequent scroll failed because the wrong selection had changed the menu state. Evidence: `red.log` and `red/`. Correcting row sizing exposed the popup hit-test conflict separately (`green.log`, `rows-fixed-hit-test-red/`).

The correction confines ordinary button styling to `#lobby-canvas` gives selector preview/menu labels 28-pixel rows, and places the popup above Settings at z-index 95, matching the existing import selector. No rules, payloads, policies or persistence formats change. The existing menu scrolling and selection behavior are retained. A fixture initially sent one wheel event with magnitude -20; LDLib advances one notch regardless of magnitude. Sending repeated real wheel events corrected that test, after which all 22 checks passed (`green-final.log`, `green-1280/`). Its failed run is preserved in `scroll-fixture-failure/`.
