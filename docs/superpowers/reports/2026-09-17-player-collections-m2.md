# Milestone 2 — persistent collections and saved lists

Implementation branch: `codex/player-collections`, worktree `.superpowers/worktrees/deck-editor`. Baseline was the approved M1 reconciled onto main, not the abandoned duplicate editor work. Milestone verification is recorded here; root's independent broad review follows this handoff. No merge or push is included.

## Delivered behavior

Private player attachments preserve immutable collection counts and saved lists, including ordered Main/Extra/Side, UUID, name, revision and active selection. Invalid stored data stays unreadable with its original raw tag; management returns DATA_UNAVAILABLE instead of repairing it. The attachment is serializable and copies on actual death/respawn.

The service owns Save, Delete, Activate, Clear Active and internal count replacement. Saving well-formed unowned or incomplete lists is permitted. Activation requires known cards, supported structure/type checks and deposited ownership across all three sections. Saving/activating lists never consumes or reserves copies. Revisions and busy state reject stale or forbidden mutations; changes that invalidate active eligibility clear selection while retaining the saved list.

Authenticated main-thread payload handlers return private bounded pages/replies to the sender. Clients publish only complete snapshots, match request/connection generations and acknowledge the exact submitted Save before clearing dirty state. Real catalog metadata loads once through separate read-only JDBC connections, and search work ignores obsolete generations. The saved-list picker supports New, Rename, Duplicate, Delete, Activate, Clear Active and Refresh; dirty navigation uses Save/Discard/Cancel. Unknown passcodes remain removable from saved lists.

## Decisions and provenance

- M1's latest user-approved dark duel-UI styling supersedes the light HTML prototype; geometry and interaction remain the prototype references. This milestone preserves that correction. Historical M1 matrix/group totals belong to the [M1 report](2026-09-17-deck-editor-m1.md), not to fresh M2 verification.
- The contract defines five service operations; the plan's earlier six was a typo, not an authorization for another operation.
- Task 4 was reviewed as infrastructure 4A and editor lifecycle 4B because asynchronous request/query work and widget navigation have distinct failure modes. Save acknowledgement remains successful even if its later refresh fails; stale in-flight pulls cannot satisfy a mutation's newer revision.
- Dirty activation requires Save first, preventing an older stored list from silently replacing the visible draft. Deleting an active list reports successful deletion with cleared active ID; it does not invent eligibility errors for a removed list.
- Runtime Task 5 was split into normal UI/respawn 5A, dedicated privacy 5B and retained-world lifecycle 5C. The automatic LDLib2 solo runner and MP orchestrator create/delete worlds, so they cannot prove an existing save survives a process restart.
- Native inputs are unchanged. The normal full test invocation used the working native prerequisite pipeline and actual JNI tests. Earlier Java-only checks could reuse the copied DLLs; that was not a substitute for JNI execution.
- The pinned MP coordinator's `new ServerSocket(0)` binds wildcard despite its loopback log. A strictly guarded generated build-only source expression confines that control hub to IPv4 loopback; game server properties also bind loopback. No global firewall, production protocol, upstream dependency or coordinator logic replacement was introduced.
