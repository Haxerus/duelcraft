## Proposed design priorities — not approved

1. Compare three genuinely distinct compositions before selecting tokens or implementing widgets. Keep the same representative content and difficult states in each so the critique concerns hierarchy, density, spacing, typography and artwork treatment, not missing functionality. Home, populated editor and an active lobby state should demonstrate each direction; include the duel right-panel behavior in the selected direction's follow-up.
2. Give Home a clean menu against the featured-monster fade. Remove the need for a large decorated menu container inside the composition; reserve short status text for actual deck/invitation problems.
3. Preserve the editor's spatial model and rich filters. Prioritize card area, an obvious editable deck name, clear Save/Use for duels state, a simple My decks dialog and separate file tools. Replace permanent instructional captions with concise control labels or contextual feedback where needed.
4. Recompose the lobby around the current decision. Player selection, invitation response and RPS need distinct arrangements within one coherent screen; they do not all need to occupy the same empty fixed frame. Keep deck selection/settings reachable where the state permits them.
5. Define log/zone expand, restore and close explicitly. An expanded panel must preserve the other panel's state and reading position; restoring must return to a useful split without obscuring essential field controls.
6. After critique, write one style guide covering surface hierarchy, type sizes, spacing, controls/focus/disabled states, popup stacking, long content and Escape/close semantics. Check both empty and populated layouts and open dropdowns before translating approved mockups into LDLib2.
