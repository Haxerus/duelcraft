# Core C API and duel lifecycle

Use this page to implement a native adapter or FFI binding. Scope: Duelcraft's core `122e0d09`, API **11.0**. See [source versions](source-versions.md) before applying it to another binary. [Index](README.md) · [data callbacks](data-and-scripts.md) · [protocol](protocol.md).

## Binding contract

The public surface is the 13 functions in [ocgapi.h](../../native/ygopro-core/ocgapi.h#L29). Include that header and [ocgapi_types.h](../../native/ygopro-core/ocgapi_types.h); obtain constant values from [ocgapi_constants.h](../../native/ygopro-core/ocgapi_constants.h). `OCG_Duel` is an opaque `void*`. The implementation casts it to `duel*`; it is neither a network identifier nor a serialized state.

The structs use the compiler's native C layout, including pointer alignment and padding. Message bytes use a different, field-by-field format. For FFI, preserve field order, integer widths, callback signatures, calling convention, and the target architecture's layout. Prefer a small C/C++ adapter when the foreign language cannot express the layout reliably. Do not assume `sizeof(loc_info)` equals its wire size.

| Native type | Fields in declaration order | Integration consequence |
|---|---|---|
| `OCG_Player` | `u32 startingLP, startingDrawCount, drawCountPerTurn` | These initialize each team's LP and draw rules. |
| `OCG_DuelOptions` | `u64 seed[4], flags`; two `OCG_Player`; callback/payload pairs for data, script, log, data-done; `u8 enableUnsafeLibraries` | Initialize the whole struct to zero, then assign all required inputs. Keep callback code and payloads alive through destruction. |
| `OCG_NewCardInfo` | `u8 team, duelist`; `u32 code`; `u8 con`; `u32 loc, seq, pos` | Owner team and current controller are distinct. A sequence is context-dependent. |
| `OCG_QueryInfo` | `u32 flags`; `u8 con`; `u32 loc, seq, overlay_seq` | Query flags select data fields. Location is not a union of arbitrary zones. |
| `OCG_CardData` | See [database mapping](data-and-scripts.md) | `race` is 64-bit; `setcodes` is a pointer to zero-terminated 16-bit values. |

Source: [type declarations](../../native/ygopro-core/ocgapi_types.h#L36). Here `u8/u16/u32/u64` denote fixed-width unsigned integers, not language-specific `long` sizes.

## Every exported function

| Function | Preconditions and result | Ownership / next action |
|---|---|---|
| `OCG_GetVersion(int*, int*)` | Writes major/minor; either output pointer may be null. | Compare with the adapter's supported API before creating a duel. |
| `OCG_CreateDuel(OCG_Duel*, const OCG_DuelOptions*)` | Non-null options pointer; non-null required readers; seed not all zero. Returns creation status, **not** a handle. | Initialize output handle to null; use it only after status `SUCCESS`. |
| `OCG_DestroyDuel(OCG_Duel)` | Null is accepted. A non-null handle must be live. | Destroys core state, cards, effects, groups, and Lua state. Clear the host's handle afterward. |
| `OCG_DuelNewCard(OCG_Duel, const OCG_NewCardInfo*)` | Add initial cards before start; calls data/script machinery and may initialize effects. Returns void. | Invalid or unavailable placements can produce no card. Verify initial zone counts. |
| `OCG_StartDuel(OCG_Duel)` | Initial setup complete. | Enqueues `Processors::Startup`; it does not run the duel. Call once in the normal lifecycle. |
| `OCG_DuelProcess(OCG_Duel)` | Live, started duel; if awaiting, submit the intended response first. | Advances until output or a non-continue status. Drain messages on **every** return status. |
| `OCG_DuelGetMessage(OCG_Duel, u32*)` | Live duel. | Returns core-owned message bytes; copy them before another operation can mutate them. Does not consume previously generated bytes. |
| `OCG_DuelSetResponse(OCG_Duel, const void*, u32)` | Host has a pending prompt and a matching response. | Copies input; another call overwrites it. Does not advance or authenticate the player. |
| `OCG_LoadScript(OCG_Duel, const char*, u32, const char*)` | Supply script bytes and a diagnostic name. | Executes synchronously; returns 1 on success, 0 on failure. Use for base scripts or inside the script-reader callback. |
| `OCG_DuelQueryCount(OCG_Duel, u8, u32)` | Team 0/1 and one supported location bit. | Returns count, or zero for invalid/unsupported selection. |
| `OCG_DuelQuery(OCG_Duel, u32*, const OCG_QueryInfo*)` | Single card coordinates. | Returns core-owned query bytes or null. See the overlay caveat in [queries](queries.md). |
| `OCG_DuelQueryLocation(OCG_Duel, u32*, const OCG_QueryInfo*)` | One controller/location. | Returns a separate location-query stream; copy before another query. |
| `OCG_DuelQueryField(OCG_Duel, u32*)` | Live duel. | Returns structural field snapshot, not a full saved duel or all card properties. |

Implementation: [creation and insertion](../../native/ygopro-core/ocgapi.cpp#L23), [start/process/message/response/script](../../native/ygopro-core/ocgapi.cpp#L106), [queries](../../native/ygopro-core/ocgapi.cpp#L140).

The core's [README API section](../../native/ygopro-core/README.md#L65) still shows some struct parameters by value and says all option pointers are mandatory. The compiled header takes **pointers to structs**; the implementation supplies no-op defaults for absent log and data-done handlers. Use the compiled source contract above.

## Creation statuses

| Value | Symbol | Cause in this snapshot |
|---|---|---|
| 0 | `OCG_DUEL_CREATION_SUCCESS` | Created and wrote the output handle. |
| 1 | `OCG_DUEL_CREATION_NO_OUTPUT` | Null output-handle pointer. |
| 2 | `OCG_DUEL_CREATION_NOT_CREATED` | The top-level `new (std::nothrow) duel` returned null. |
| 3 | `OCG_DUEL_CREATION_NULL_DATA_READER` | Missing `cardReader`; output set to null. |
| 4 | `OCG_DUEL_CREATION_NULL_SCRIPT_READER` | Missing `scriptReader`; output set to null. |
| 5 | `OCG_DUEL_CREATION_INCOMPATIBLE_LUA_API` | Lua failed the C++ stack-unwinding check; partial duel deleted. |
| 6 | `OCG_DUEL_CREATION_NULL_RNG_SEED` | All four seed words zero. |

Source: [enum](../../native/ygopro-core/ocgapi_types.h#L20), [checks](../../native/ygopro-core/ocgapi.cpp#L23), [Lua compatibility probe](../../native/ygopro-core/interpreter.cpp#L31). Some failure paths leave the caller's previous output value untouched. The implementation dereferences `options_ptr` without a null check. Treat argument validation and exception containment at a foreign-language boundary as adapter responsibilities; the C exports are not a universal exception-to-status layer.

## Normal host lifecycle

1. Load a matching library and verify the API. Construct a per-duel callback context with accessible card records and scripts.
2. Initialize options, including four reproducible nonzero-as-a-group seed words, 64-bit rule flags, and both teams' LP/draw values. Create the duel and check status.
3. Load the script pack's base scripts in the host-defined order. Fail setup if a required base script fails; see [data and scripts](data-and-scripts.md).
4. Validate and order decks in the host. Insert cards for both teams; verify counts. Preserve the insertion order if you need replay.
5. Call `OCG_StartDuel`, then pump. Copy and parse each complete message batch before calling process again.
6. On a prompt, publish a player-specific view and retain the prompt's exact ordered choices. On a valid response, encode the prompt's response format, call set-response, and resume pumping.
7. On end/cancellation/error, finish host notifications and destroy once. Release callback contexts and unload the library only after its live duels are gone.

### Pump pseudocode

This is a host design recipe, not a compiled example. `dispatch_in_order` includes recipient filtering and query refresh policy; `pending_prompt` belongs to the host.

```text
pump(duel):
    loop:
        status = OCG_DuelProcess(duel)
        length = 0
        pointer = OCG_DuelGetMessage(duel, &length)
        batch = copy(pointer, length)          # zero length => empty batch
        dispatch_in_order(parse_frames(batch))

        if status == END:
            finish_and_destroy(duel)
            return
        if status == AWAITING:
            require_pending_prompt_or_report_protocol_error()
            return                            # wait outside the core
        require(status == CONTINUE)

receive_response(session, sender, prompt_id, answer):
    validate_session_sender_and_pending_prompt(session, sender, prompt_id)
    bytes = encode_and_validate(session.pending_prompt, answer)
    OCG_DuelSetResponse(session.duel, bytes.data, bytes.length)
    pump(session.duel)
```

Status values are `END=0`, `AWAITING=1`, `CONTINUE=2`. In [OCG_DuelProcess](../../native/ygopro-core/ocgapi.cpp#L111), each call clears the message buffer first, then repeatedly runs a processor while no messages exist and status is continue. A continue result can contain meaningful messages. A waiting result can contain several messages before the prompt. An end result still deserves a drain. `END` itself does not encode winner/reason; those belong to `MSG_WIN` and host session policy.

Do not poll process while awaiting user input: [field::process](../../native/ygopro-core/processor_visit.cpp#L9) advances the current processor's step, and the next step reads response storage. `OCG_DuelGetMessage` generates queued messages into the existing buffer; calling it twice without a process does not mean two new batches. See [duel::generate_buffer and set_response](../../native/ygopro-core/duel.cpp#L103).

## Memory and callback lifetimes

| Object | Owner | Safe host rule |
|---|---|---|
| Options struct and insertion/query structs | Host | May be stack-local for their synchronous API calls. The core copies options and retains callback pointer/payload values. |
| Callback function and payload objects | Host | Retain for the entire duel lifetime, including nested script reads during insertion. |
| Data reader's `setcodes` allocation | Host | Keep valid until data-done; the core copies values into its per-duel cache before that callback. |
| Response input bytes | Host | Reuse after `OCG_DuelSetResponse` returns. |
| Script input bytes | Host | Keep valid during the synchronous load; the core compiles/executes them before returning. |
| Message output pointer | Core `duel::buff` | Copy before further processing or returning to asynchronous code; never free. |
| Query output pointer | Core `duel::query_buffer` | Shared by all query functions on that duel; copy before the next query; never free. |
| Duel handle | Core allocation, host lifecycle control | Destroy exactly once; never call another API on a destroyed handle. |

Source: [duel members](../../native/ygopro-core/duel.h#L63), [construction/destruction](../../native/ygopro-core/duel.cpp#L15), [read_card and copy-before-done](../../native/ygopro-core/duel.cpp#L148), [script execution](../../native/ygopro-core/interpreter.cpp#L220).

## Concurrency and scheduling

**Host recommendation:** serialize create/setup/process/query/response/destroy for each duel on one executor or under one ownership discipline. The exported functions mutate state without a per-duel lock, and callback calls occur inline. The source exposes no cancellation token, async callback protocol, per-call time budget, or save/restore API. Do not infer a general cross-thread safety guarantee from separate handles. Any shared database/script caches also need their own concurrency policy.

The script reader's call back into `OCG_LoadScript` is an intended nested operation. Arbitrary reentrant processing, destruction from a callback, or parallel queries on the same duel are not established contracts. For hosts needing a hard execution timeout, process isolation is a host design option; forcibly freeing a running native duel is not a timeout mechanism.
